H. 结构化 txt 往返 + 卷册 真浏览器专属

验的是"导出成文本 → 再导入回来"在浏览器里是否逐字段无损、损坏文本会不会被拦下、以及失败时真实 localStorage 是不是一个字节都没动。同时确认这两个模块内联进单文件 HTML 后能正常挂载。

I. 关掉/刷新浏览器后数据还在吗 两阶段·需要刷新一次

这一节验「重启浏览器后试卷、题目与设置仍在」，而且 localStorage 与 IndexedDB 两条路径各验一次。
只有"重新加载过页面"才算数 —— 同一次加载里读写两次证明不了持久化。所以它是两阶段的：
① 第一次点开本页 → 写入探针（小记录进 localStorage、2000 字符的大记录进 IndexedDB），然后停下；
② 你刷新本页（F5 / Ctrl+R）→ 本节复核数据是否还在，并检查落点索引与 keys()，最后自动清理。

J. 快捷面板：行为开关 / 展示时机 / 分数线 真浏览器专属

这一节验的是只有浏览器能给的部分：按钮与输入框的触屏点击目标够不够大（≥44px）、 点一下是不是真的改了配置、非法值会不会被拦下并给出提示。 答案会不会泄露那部分在 core/flow.js 里是纯函数，Node 侧已穷举断言； 这里只验"界面把点击正确转成了配置改动"。

K. 作答界面与触屏 真浏览器专属

这一节验的是只有浏览器能给的部分：375px 手机宽度下会不会横向滚动、 点击目标是否 ≥44px、四种题型是不是都画出了对应控件、 以及在底部面板改设置后不跳页就立刻生效（改完直接提交下一题，答案区当场出现）。
建议：按 F12 打开设备工具栏切到手机宽度再看一眼，本节的容器就是按 375px 卡出来的。

L. 作答进度：刷新后还在吗 两阶段·需要刷新一次

这一节验「作答内容与当前题号写进本地存储、刷新后能恢复、交卷后清理干净」。
只有"重新加载过页面"才算数 —— 同一次加载里读写两次证明不了持久化。所以它是两阶段的：
① 第一次点开本页 → 写入一份进度探针（真实 localStorage，键名走试卷命名空间规则），然后停下；
② 你刷新本页（F5 / Ctrl+R）→ 本节复核：作答与题号是否原样恢复、恢复后能否继续答、 交卷后键是否被清掉，最后自动清理。

M. 错题本：分卷归集 / 逐题详情 / 跳回原卷 真浏览器专属

这一节走**真数据**：拿内置样卷真答一遍 → 真交卷 → 真收集进错题本，再把它挂到 375px 宽的容器里验 「按卷分组、计数与判分一致、点一条能看到原题/参考答案/解析、点『跳到这道题』能精确回到那一题」。
还专门验一条硬规矩：原题一律从试卷现读 —— 题干改过会显示卷子里的最新版并标出提醒， 题被删掉则如实说明并禁用跳转（绝不拿错题本里的旧快照冒充原题）。

N. 删卷级联询问：两条路径都不留孤儿 真浏览器专属

这一节走**真存储**（真 localStorage）：造两套临时卷 → 各挂一份错题本与作答记录 → 用真实弹窗分别选『否』（保留记录）与『是』（一并删除），再断言 「卷没了 / 记录留下且有『已删除试卷』归属标识 / 键扫描零孤儿 / 级联路径零残留」。
验的正是只有浏览器能给的那部分：弹窗的遮罩层级、触屏点击目标 ≥44px、 以及"点遮罩空白处 = 取消、不点就不写盘"。末尾会把两套临时卷与残留记录**全部清理掉**。

O. AI 密钥：刷新后还在吗 + 能力表标注 两阶段·需要刷新一次

这一节验「填进去的 Key 在**真浏览器刷新**之后仍然保留，并且真的能用于调用」。
只有"重新加载过页面"才算数 —— 同一次加载里读写两次证明不了持久化。所以它是两阶段的：
① 第一次点开本页 → 通过界面真的填一把探针 Key（写的**真实 localStorage**，独立命名空间 secret），然后停下；
② 你刷新本页（F5 / Ctrl+R）→ 本节复核：Key 是否还在（遮罩显示）、readKey 能不能读回原文、 能力表里"不可直连"的家是否被明确标注、界面是否只显示遮罩（DOM 里不留原文），最后自动清理。

P. 单题智能生成：解析 / 变式题 / 难度 真浏览器专属

这一节验「单题按钮点一次只发一次请求」「结构不合格的结果**不会**落到草案上」「三类结果各自写对地方」。 联网部分用**注入的假 fetch** 顶替（不花钱、可重复）：真 Key 的真调用由 node verify/real-ai.js 负责（读环境变量，人工触发）。
想在这里看真调用：先去「校对面板」填一把 Key，再用那个页面的「单题智能」按钮。

Q. 整卷点评与举一反三 真浏览器专属

这一节验两个**场景化**能力：交卷后的「整卷总评」（**先弹消耗确认窗**，未确认不发请求； 总评必须引用本轮真实得分/错题，套话会被拒）与错题本的「举一反三」（**不弹确认窗**， 一次点击一次请求；生成的新题能一键加进那套卷并出现在对应题型分组里）。
联网部分用注入的假 fetch（不花钱、可重复）；真 Key 的真调用由 node verify/real-ai.js 负责。

R. 容错与提示：脏输出 / 错误分类 / 批量消耗确认 真浏览器专属

这一节验三件事：脏输出容错（12 类里挑几类在浏览器里再过一遍）、 三类失败的可操作提示（断网 / 密钥错 / 模型不支持 JSON 模式）、 以及批量先确认（未确认零请求、确认后逐题跑；单题不弹窗）。
「估算 token 偏差」用真调用实测：命令行 node verify/real-ai.js 会把 estimate/actual 写进 verify/real-ai-last.json（本次实测单题 5.1% / 总评 8.6% / 批量 21.9%，阈值 60%）。
